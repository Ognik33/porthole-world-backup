# Протокол хелпера world_backup

Версия протокола: **1**. Хелпер `world_backup.dll` запускается дополнением через `porthole.run_helper`
в режиме `--agent <порт> <токен> [секунды]`, один процесс на сессию лобби.

Если за указанное число секунд (по умолчанию 60) не пришло ни одной команды с верным токеном,
хелпер выводит `error reason=idle_timeout` и завершается. Дополнение шлёт `ping` раз в ~10 с,
поэтому тишина означает, что дополнение больше не работает, и хелпер не остаётся сиротой.

## Транспорт

- **Команды** идут от Luau к хелперу по TCP на `127.0.0.1:<порт>`. Хелпер слушает только loopback.
- Подходят оба способа отправки Porthole:
  - `porthole.tcp_open(port)`: одно постоянное соединение, основной способ;
  - `porthole.tcp_send(port, text)`: соединение на каждую команду, запасной способ.
- Хелпер держит до 16 соединений одновременно и выполняет каждую строку сразу, как только она
  пришла. Строка без LF перед закрытием соединения тоже выполняется.
- **События** идут от хелпера к Luau строками stdout (`run_helper.on_output`). В сокеты хелпер
  ничего не пишет.

## Формат

Команда, одна строка:

```
<токен> TAB <команда> [TAB <аргумент>]... LF
```

- Токен: случайная строка 16..64 символа, её знает только дополнение. Строка с чужим токеном
  даёт `error reason=bad_token`, и это соединение закрывается.
- CR перед LF и пустые строки игнорируются. Строка длиннее 64 КБ закрывает соединение
  (`error reason=line_too_long`).

Событие, одна строка: `<вид> [TAB ключ=значение]...`. Значения всегда валидный UTF-8 без TAB, CR и LF.

## События

| Событие | Когда |
|---|---|
| `hello proto=1 version=<версия> caps=<список>` | сразу после запуска |
| `ready port=<порт>` | хелпер слушает порт и принимает команды |
| `pong` | ответ на `ping` |
| `error reason=<код> [detail=<текст>]` | ошибка; `bind` (порт занят) и `idle_timeout` (нет команд) означают, что хелпер сейчас выйдет |

`caps` в версии 0.0.1: `persist` (хелпер понимает постоянные соединения).

## Команды

| Команда | Ответ | С какой версии |
|---|---|---|
| `ping` | `pong` | 0.0.1 |
| `quit` | хелпер завершается | 0.0.1 |
| `resolve <port>` | см. ниже | 0.0.5 |
| `backup <seq> <мир> <папка копий> <clean\|hot> <0\|1>` | см. ниже | 0.0.6 |
| `list <seq> <папка копий> <мир>` | `copy seq= file= kind= bytes= time= local=` ... `list_done seq= count= folder=` | 0.0.6 |
| `prune <seq> <папка копий> <мир> <N> <M> [лимит МБ]` | `removed seq= file=` ... `pruned seq= count= freed=` | 0.0.6 |
| `space <seq> <путь>` | `space seq= free= total=` или `space_error seq=` | 0.0.6 |
| `paths` | `paths backups=<Документы>\Porthole Backups` | 0.0.6 |
| `pickfolder` | `pickfolder path=` или `pickfolder cancel` | план, шаг 3 |
| `open <путь>` | открывает папку в Проводнике | план, шаг 3 |
| `watch` / `unwatch` | копия при закрытии мира силами хелпера | план, шаг 3 |

Неизвестная команда: `error reason=bad_command detail=<команда>`.

### resolve

Какой мир открыт на порту. Ответ приходит сразу (миллисекунды), строки помечены портом.

```
candidate port= world=<путь> name=<папка> locked=1|0|? lock_age_s=     только при method=ask, новые первыми, до 20
world port= pid= exe= launcher=vanilla|multimc|prism|unknown source= gamedir= saves=
      method=lock|mtime|ask world=<путь или пусто> name= worlds=<миров в saves> candidates= [diag=]
resolve_error port= reason=bad_port|no_listener|no_gamedir|no_saves [gamedir= source= launcher= diag=]
```

- `source`: откуда взята папка игры: `gameDir`, `gameDir+cwd` (относительный `--gameDir`),
  `targetdir`, `targetdir+cwd` (старые лаунчеры), `cwd` (рабочая папка процесса, MultiMC и Prism).
- `method`: `lock` (session.lock занят игрой), `mtime` (session.lock изменён после запуска игры),
  `ask` (ни одного или несколько кандидатов: спросить человека).
- Миром считается папка в `saves`, где есть `session.lock`.
- `diag`: что не удалось прочитать, например `cwd:open` или `cmdline:query`; для разбора проблем.
- Из командной строки игры наружу попадает только значение `--gameDir` и маркер лаунчера.

### backup

Копия мира в отдельном потоке; агент в это время отвечает на другие команды. Одновременно идёт
одна копия, вторая получает `backup_error reason=busy`. Последний аргумент: `1`: не копировать,
если мир не менялся с последней копии (для `clean` сравнивается с чистыми, для `hot` с любыми),
`0`: копировать всегда (кнопка «Сделать копию сейчас»).

```
backup_start seq= file=<итоговый путь> bytes=<размер мира> files=
progress seq= pct= bytes=                       не чаще 4 раз в секунду
backup_done seq= file= bytes=<размер архива> src_bytes= files= skipped= ms=
backup_skip seq= reason=unchanged last=<имя последней копии>
backup_error seq= reason=bad_args|busy|no_world|bad_root|walk|mkdir|marker|folder_conflict|no_space|memory|create|read|write|rename|cancelled [detail=]
```

- Папка копий мира: `<папка копий>\<имя папки мира>`, в ней скрытая метка `.world-backup` с путём мира.
  Занята другим миром или чужая (без метки): `<имя> (<8 hex хеша пути>)`.
- Архив: `<ГГГГ-ММ-ДД_ЧЧ-ММ-СС>_<clean|hot>[_<n>].zip` по местному времени начала копии. Время
  изменения архива выставляется равным началу копии.
- Пишется в `<архив>.tmp`, переименовывается целиком готовым. Брошенные `.tmp` с нашим шаблоном имени
  удаляются в начале следующей копии этого мира. При выходе хелпера копия отменяется, `.tmp` удаляется.
- `session.lock` в архив не попадает. Горячая копия пропускает файлы, которые не удалось открыть
  (`skipped=`), чистая в этом случае завершается ошибкой `read`.
- Место: нужно не меньше размера мира + 10 % + 256 МБ, иначе `no_space` до начала записи.
- Сжатие: deflate уровня 3; файлы регионов (`.mca`, `.mcr`, `.mcc`) в режиме RLE, вдвое быстрее при
  том же размере (чанки внутри уже сжаты игрой).
- ZIP64 включается сам: файл от 0xF0000000 байт, архив больше 4 ГБ, больше 65 534 записей.

### prune

Удаляет только архивы с нашим шаблоном имени. Оставляет N последних чистых (минимум 1) и M горячих;
с лимитом в МБ дополнительно удаляет самые старые из оставшихся, но никогда последнюю чистую.

### CLI

Для проверки без Porthole: любая команда агента без токена, `--cmd <команда> [аргументы]`
(ждёт конца копии), например `world_backup_cli.exe --cmd backup 1 "C:\...\saves\Мир" "D:\Копии" clean 0`.
Определение мира: `world_backup_cli.exe --resolve <port>`, `--resolve all`
(все порты процессов java/javaw) и `--resolve-pid <pid>`.

## Как Luau выбирает канал

1. После `ready`, если в `caps` есть `persist` и в Porthole есть `tcp_open`, открывается
   постоянное соединение, по нему уходит `ping`.
2. Хелпер считается готовым только после `pong`.
3. Если `tcp_open` нет, он бросает ошибку или `pong` не пришёл за ~5 с, дополнение переходит на
   `tcp_send` и запоминает это до перезапуска Porthole.
4. Если `send` по постоянному соединению бросил ошибку посреди сессии, та же команда сразу
   уходит через `tcp_send`.
5. Дальше `ping` раз в ~10 с. Нет `pong` за ~5 с: хелпер перезапускается с паузой
   5, 10, 20, 60 с; после минуты нормальной работы счётчик неудач сбрасывается.

## Безопасность

- Хелпер читает командную строку чужих процессов только ради `--gameDir` и никогда не выводит её
  целиком: обычный лаунчер Minecraft передаёт там токен входа.
- В этапе 1 хелпер пишет файлы только в папку копий (по умолчанию `Документы\Porthole Backups`
  или та, что выбрана во вкладке). Миры он только читает.
