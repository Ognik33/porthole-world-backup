# Бэкап миров: дополнение для Porthole

[English](README.md)

Автоматические резервные копии миров Minecraft Java, которые вы хостите через [Porthole](https://store.steampowered.com/app/4963920).

> **Статус: в разработке.** Версии 0.0.x тестовые. Они запускают хелпер дополнения и проверяют
> связь с ним. Копии миров пока не делаются.

## Что будет в 0.1.0

- Minecraft Java с официальным лаунчером, MultiMC и Prism.
- Мир находится сам: от порта, который открыл Minecraft, до папки мира.
- Копия при закрытии мира. По желанию «горячие» копии раз в N минут, пока мир открыт.
- Один вопрос при первом закрытии мира, дальше дополнение действует по ответу.
- Последние N копий каждого мира в одной папке, по умолчанию `Документы\Porthole Backups`.
  Копии лежат обычными zip-архивами, как у кнопки «Создать резервную копию» в самой игре.
- Вкладка с мирами, их копиями и папкой для копий.

Позже: друзья из лобби скачивают копию мира и продолжают играть у себя.

## Установка

1. Скачайте `world-backup-<версия>.paddon` из [Releases](https://github.com/Ognik33/porthole-world-backup/releases).
2. **Выйдите из лобби** (в лобби дополнения менять нельзя).
3. Porthole → Настройки → Дополнения → «Установить из файла» или перетащите файл в окно.
4. Включите дополнение и создайте лобби или зайдите в него. Вкладка «Бэкап миров» покажет, работает ли хелпер.

## Разрешения и зачем они

| Разрешение | Зачем |
|---|---|
| `ui` | вкладка и уведомления |
| `identity` | в лобби ли вы: хелпер работает только во время сессии |
| `system` | видеть, какие программы слушают порты (`on_listening`), и отправлять команды своему хелперу на `127.0.0.1` |
| `run_helper` + `natives` | запуск `world_backup.dll`: поиск папки мира и копирование |

Без прав администратора. Дополнение не ходит в интернет. Порт команд хелпера слушает только
`127.0.0.1` и принимает команды только со случайным токеном, который знает дополнение.
Командную строку чужой программы хелпер читает только ради `--gameDir` и никогда не пишет её
в лог: официальный лаунчер передаёт там токен входа в аккаунт.

## Как устроено

- **Luau** (`src/*.luau`, при сборке склеивается в один `main.luau`) решает, что делать: когда
  делать копию, о чём спросить, что показать.
- **world_backup** (`native/*.c`, одна DLL) делает всё, что трогает файлы и процессы.
  Один процесс на сессию, команды только с токеном, события строками в stdout.
  Подробно: [docs/protocol.md](docs/protocol.md).

## Сборка и тесты

Нужны `mingw-w64`, `python3` (3.11+), `zip` (Linux или WSL) и [`luau`](https://github.com/luau-lang/luau/releases) для тестов Luau:

```
sudo apt install gcc-mingw-w64-x86-64 zip python3
./tools/test.sh          # тексты, протокол хелпера, юнит-тесты и сценарии Luau
./tools/build.sh         # -> dist/world-backup-<версия>.paddon, dist/world_backup_cli.exe
./tools/check_repro.sh   # собирает два раза и сравнивает хеши
./tests/win/smoke.sh     # необязательно: определение мира под Wine с поддельной игрой
```

Сборка воспроизводимая: `.paddon` в Releases (его собирает GitHub Actions из этого кода) бит в бит
совпадает с локальной сборкой тем же компилятором.

## Совместимость и ограничения

- Проверено на Porthole 3.0.2, API дополнений версии 1. SeStudio называет API нестабильным, поэтому
  обновление Porthole может потребовать исправлений.
- Только Windows.
- Только Minecraft Java.
